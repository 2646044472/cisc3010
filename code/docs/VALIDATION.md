# Initial demo validation — 13 October 2026

All observations below come from actual local executions. This is an initial demo, not the final course report.

## Environment

- Windows 11, Python 3.13.9, confluent-kafka/librdkafka 2.16.0.
- Intel Core Ultra 5 338H, 12 logical processors, approximately 31.5 GiB RAM; all components share this machine.
- Apache Kafka 4.3.1, one KRaft broker, replication factor one. Native JVM launcher tested using Temurin Java 25.0.3, heap 256–512 MB.
- Docker Desktop could not start because of a local `sailor-ingest.sock` access error. Compose configuration passes validation, but container startup was **not** tested. The working broker uses the official Java distribution, with SHA512 verified.
- An initial metadata connection attempt failed when localhost resolution selected IPv6 while the broker listened on IPv4. All clients now explicitly use IPv4; the original failed run remains in `runs/20261013T052554-c409ac9d/error.json`.
- Native broker stop/start was tested without deleting its data; the subsequent browser-driven idempotent run passed.
- Exact installed Python dependencies are recorded in `validation-environment.txt`. Optional figure generation uses matplotlib 3.11.2 (requires Python 3.11+).

These values include group detection/joining and polling; they are not pure internal rebalance durations. Standalone six-consumer/four-partition smoke test also completed with 24 correct effects. Browser-driven idempotent recovery with 120 events completed with one replayed ID and no missing/duplicate effects; independent CLI rechecking passed.

## Fixed-partition consumer-count experiment

Command: `python -m kafka_demo experiment --counts 1,2,4,6 --repeats 3 --events 240 --processing-ms 15`.

Four partitions, fixed seed and event values/mapping, finite burst, 15 ms synthetic application delay per event, synchronous per-message commits, durable SQLite effects. An eight-event warmup was excluded. Count order alternated between repetitions. The elapsed interval starts with production and ends when the controller observes every event committed; startup and graceful shutdown are excluded.

| Consumers | Repetitions | Mean unique effects/s | Sample standard deviation |
|---:|---:|---:|---:|
| 1 | 3 | 35.96 | 0.37 |
| 2 | 3 | 58.98 | 4.63 |
| 4 | 3 | 52.37 | 5.29 |
| 6 | 3 | 55.87 | 2.30 |

All 12 measured runs passed business correctness. Timeline reconstruction verified exactly one owner for each partition at workload start in all 12 runs and the warmup. The controller additionally waits for exclusive complete assignment and a short quiet interval before new runs produce data.

The observed improvement from one to two consumers does not continue linearly. This small shared-host pipeline includes producer activity, per-message commits, serialized SQLite writes, scheduling, fixed delays and 100 ms completion observation. The measurements do not isolate those costs and cannot establish Kafka broker capacity or prove one particular cause of the plateau. Six consumers can only actively consume four partitions in this group. Repeat with larger workloads or additional instrumentation before generalizing.

Raw evidence and traceable figures: `sample-results/experiment-20261013T053530-f8d167/`. `results.csv` holds individual measurements, `summary.csv` holds variation, and each nested run includes its raw audit database/exports and checker result. `throughput.png` and `throughput.svg` were generated by `scripts/plot_results.py`, which checks CSV/raw-result consistency before plotting.

## Other checks

- Six unit tests passed: value corruption, missing/unexpected/unpublished input, duplicate effects, visible replay with idempotent effects, atomic rollback of dedup marker on write failure, config rejection and reproducible data.
- Browser: actual button starts a run; controls lock while running; real assignments/PIDs/crash/restart/dedup appear; completion verdict distinguishes scenario verification from business correctness.
- HTTP rejects invalid event count with status 400. No run is started by this invalid request.
- External interruption of a separate active test server left zero consumer processes for its run ID; that interrupted run did not finish or generate normal exports. The final main server and broker remain running.
- Python modules compile; Compose YAML validates.
